## 절대 발생하면 안 되는 결과

LinkedIn의 다른 기기 세션을 자동 종료하거나, `li_at`·비밀번호·쿠키 원문을 로그·영수증·모델 대화에 노출해서는 안 된다. 이를 막는 기계 통제가 없는 단위는 완료로 판정하지 않는다.

## 실행 원칙

1. 아래 순서를 바꾸지 않고 한 번에 한 단위만 구현한다.
2. 각 단위는 실패 검사 커밋, 최소 구현 커밋, 전체 검사, 자기 반증, Claude 새 문맥 반증, Codex 재현을 거친다.
3. 반증에서 결함이 나오면 그 결함을 잡는 실패 검사를 먼저 추가한 뒤 고친다.
4. 같은 단위에서 정정이 두 번 생기거나 문맥이 오염되면 현재 상태·미완료 항목·정확한 다음 명령을 새 인계 프롬프트에 기록하고 새 셸에서 재개한다.
5. 브라우저·창·탭·프로필은 구현 검사 중 만들거나 닫지 않는다. 라이브 검사가 필요한 후속 단위도 정확한 기존 대상만 사용한다.
6. 각 단위가 끝날 때 이 표의 상태와 증거를 갱신한다.

## APP 01 계약 — 로그인 기준 규칙 통합

### 목표

- 사람인·잡코리아: 비밀 저장소의 사이트별 아이디·비밀번호를 정확한 기존 탭에 최대 1회 제출한다.
- LinkedIn: 아이디·비밀번호 폼 제출을 금지한다. 인증 기기 0개가 봉인된 증거로 확인되고 현재 턴 소유자 승인과 APP 17 경로 결정이 같은 기기의 정확한 기존 탭 하나를 가리킬 때만 APP 30/31이 비밀 저장소의 `LINKEDIN_LI_AT` 참조를 최대 1회 적용할 수 있다.
- 이미 인증된 LinkedIn 기기가 정확히 하나면 그 기기와 탭을 조작 0회로 재사용한다.
- 인증된 LinkedIn 기기가 둘 이상이면 terminal `AUTH_CONFLICT`로 중단한다. 다른 기기 로그아웃·Continue/Confirm·새 탭·재시도는 0회다.
- `li_at` 원문과 그 파생값은 인자·stdout·stderr·로그·영수증·산출물·모델 대화에 넣지 않는다.

### 선행 입력과 산출물

| 구분 | 입력 | 산출물 |
|---|---|---|
| 정책 충돌 | SOT 26, login 스킬, 브라우저 안전계약, 두 과거 프롬프트 | 새 버전의 사이트별 인증 정책과 대체 관계 |
| LinkedIn 기기 수 | 인증된 기기 0·1·2+ | 결정표와 terminal 중단 규칙 |
| 비밀 경계 | 저장소 참조, 로그·영수증 스키마 | 허용 메타데이터와 금지 필드 |
| 실제 연결 | login 워커 프롬프트, 검색 워커 프롬프트, 검색 스킬 | 새 정책 ID의 정적 참조 |

### 예외 처리

| 상황 | 처리 |
|---|---|
| 사람인·잡코리아 로그인 폼과 정확한 기존 탭이 유일함 | 저장 자격증명 최대 1회 제출 |
| 사람인·잡코리아 captcha·2FA·checkpoint | 추가 제출 0회, `HUMAN_AUTH` |
| LinkedIn 인증 기기 0개 + 선택 기기의 정확한 기존 탭 1개 | APP 30/31 제공자·적용기가 준비된 경우에만 `li_at` 최대 1회 적용; 현재 단위에서는 구현하지 않음 |
| LinkedIn 인증 기기 1개 | 그 기기와 정확한 기존 탭 재사용, 인증 조작 0회 |
| LinkedIn 인증 기기 2개 이상 | terminal `AUTH_CONFLICT`; 자동 로그아웃·선택·재시도 0회 |
| LinkedIn 정확한 기존 탭 0개 또는 여러 개 | 새 탭 생성 없이 `HANDOFF` |
| 비밀 제공자 또는 적용기 미구현 | 위험한 기존 아이디·비밀번호 경로로 대체하지 않고 명시적 중단 |
| 사람 활동 감지 | mutation 0회, 읽기 전용 대기 |
| 로그·영수증에 비밀 키가 들어옴 | 기록 자체를 거부 |
| 그 외 전부 | 임의 판단 없이 명시적으로 중단하고 표를 갱신 |
