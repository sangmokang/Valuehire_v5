## 2. APP 02 목표

모든 생산 경로가 아래 세 정식 기기 이름만 사용하도록 한다.

- `macmini`
- `macbook`
- `winpc`

`macbook_pro`는 외부 입력 경계에서만 `macbook`으로 바꾼다. 저장 데이터, 작업 영수증,
상태 보고, 잠금 키에는 정식 이름만 남긴다. 모르는 이름은 기본 기기로 추측하지 않고
구조화된 오류로 거부한다. 기기 자동 선택은 구현하지 않는다.

## 3. 필수 순서

1. `job_queue.py`, `fleet_args.py`, `fleet_dispatch.py`, 데이터베이스 변경 이력,
   구현 설명서의 APP 02, 구현 목표 문서를 조사한다.
2. Discord·셸 입력, 작업 큐, 배정, 환경변수, 상태 보고, 브라우저 조사 보고서, 영수증,
   계정·기기 잠금, 데이터베이스 제약, 복사본과 거울 파일의 생산 경로를 전부 찾는다.
3. 별칭 분리 잠금, 별칭 저장, 모르는 값의 기본값 전환, Discord와 실행 환경 불일치,
   큐와 데이터베이스 불일치, 보고·영수증 별칭, 대소문자·공백 허용, 공용 함수 우회,
   동일 기기의 잠금 영역 분리를 재현하는 실패 검사를 먼저 별도 커밋한다.
4. `MachineId`와 단일 `normalize_machine_id` 모듈을 만들고, 입력 경계만 별칭을 허용한다.
   내부 객체와 저장 경계는 정식 이름만 받는다.
5. 기존 저장값은 안전한 읽기 호환만 제공하고 근거 없는 일괄 수정은 하지 않는다.
6. 관련 검사, 통합 검사, 저장 별칭 0개 검사, 복사본 해시 검사, 결함 주입 검사,
   영향 범위 전체 검사를 실행한다.
7. 새 Codex 문맥에서 독립 적대 검토를 받고, 반례가 있으면 실패 검사를 먼저 추가한다.
